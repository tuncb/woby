# NoGraphicsAPI versus main: behavioral comparison

Compared on 29 September 2026: current `main` at `9eccf57` (0.22.1), in `D:/woby`, against `codex/nographicsapi-migration` at `4f91511` (0.21.3), in `D:/.worktree/5b99/woby`. The migration's production source is clean; its pre-existing uncommitted investigation documents were also read. No production code was changed for this review.

This includes the final pixel-coverage fix. The earlier claim that vertex rendering is 26–34% slower describes `188efd8`, not the implementation being reviewed. Historical performance evidence uses `97886f5`; current main differs from that revision only in version numbers and cancellation tests, not application rendering code.

“Verified” below means reproduced in this review. “Source” means established by the implementation, with any untested visual consequence stated separately. “Recorded” means existing benchmark evidence, not a new performance measurement. This is a source and targeted runtime comparison, not a claim of exhaustive pixel equivalence across every GPU and operating system.

**Additional adapter-contract differences**

These matter when extending or debugging the renderer. They are not all demonstrated regressions in an existing Woby interaction.

26. **Capability reporting is partly hard-coded.** The adapter reports a 16384 texture limit, eight compute bindings and eight framebuffer attachments, although its framebuffer implementation accepts only two color attachments plus depth. Format validation checks format usage, but not the requested 4x sample count. Main obtains backend capabilities from bgfx. Existing Woby targets fit the attachment subset; larger future requests cannot trust all reported limits. [Caps](D:/.worktree/5b99/woby/src/graphics.h:145), [format validation](D:/.worktree/5b99/woby/src/graphics.cpp:888), [framebuffer validation](D:/.worktree/5b99/woby/src/graphics.cpp:940).

27. **Clears apply to the full attachment.** The new render-pass load operation clears the entire target; the viewport is set afterward. bgfx can clear a view rectangle. Current full-window/picking clears are unaffected, but the narrower scene region of an annotated export also clears its right-hand panel area before that panel is drawn. The opaque panel normally hides this. Reusing this adapter for multiple independently cleared subviews would change behavior. [Attachment clears](D:/.worktree/5b99/woby/src/graphics.cpp:562), [render pass](D:/.worktree/5b99/woby/src/graphics.cpp:1318), [old rectangle clear](C:/work/vcpkg/buildtrees/bgfx/src/bgfx-739bf2729e.clean/bgfx/src/renderer_d3d11.cpp:3445).

28. **The per-draw MSAA flag has no effect.** Target sample count alone controls the native pipeline. Main passes `BGFX_STATE_MSAA` to the backend's rasterizer state. Most current draws set it; fin-fill and marker-highlight draws omit it. The precise visual difference for such draws depends on backend rasterization rules and was not established here. Overall desktop 4x MSAA remains; PNG targets remain single-sample. [Pipeline key/state](D:/.worktree/5b99/woby/src/graphics.cpp:592), [fin fill](D:/.worktree/5b99/woby/src/comparison_view.cpp:1924).

29. **The API is a Woby subset, not a bgfx-compatible replacement.** It only accepts single-mip/layer 2D textures, the current vertex/point/storage bindings, and named Woby uniforms. Samplers are linear/nearest with clamp-to-edge, and all blend-function requests collapse to the same alpha blend; the ID attachment is always unblended. Uniform/root state is reset after each submit. Existing reviewed draw sites populate their required fields, but future bgfx-style use cannot assume the old general behavior. [Interface](D:/.worktree/5b99/woby/src/graphics.h:13), [uniform/binding implementation](D:/.worktree/5b99/woby/src/graphics.cpp:1099), [samplers](D:/.worktree/5b99/woby/src/graphics.cpp:798).

30. **Some bad resource operations now throw synchronously.** Invalid/stale handles, invalid strides, texture updates and mismatched framebuffers are checked in the adapter. Other exhaustion paths still reach assertion-based native-library behavior. Main uses bgfx's validation, invalid handles and backend failure behavior instead. The migration tests several new exception cases; this does not establish device-loss recovery. [Validation](D:/.worktree/5b99/woby/src/graphics.cpp:224), [tests](D:/.worktree/5b99/woby/tests/graphics_tests.cpp:23).

31. **Debug/render-view naming hooks are no-ops.** `setDebug`, `dbgTextClear`, `setViewName`, and non-shader resource `setName` do not implement bgfx's debug overlay/naming behavior. This reduces graphics-debugging metadata; no normal application debug overlay was found that would now disappear from the visible UI. Shader names still determine entry points. [Hooks](D:/.worktree/5b99/woby/src/graphics.cpp:863), [view hooks](D:/.worktree/5b99/woby/src/graphics.cpp:1169), [name overload](D:/.worktree/5b99/woby/src/graphics.h:195).

**Behavior preserved in the reviewed application logic**

The diff does not change model import/parsing, analysis calculations, scene operations, transforms, camera behavior, history, selection logic, or `.woby` version-16 serialization. Mesh lighting, comparison heatmap formulas, point size, marker ID encoding and GPU lookup tie-breaking are preserved. Circular point cutout is once per pixel again after `4f91511`; MSAA geometry/depth and per-sample ID lookup remain. The old prototype's per-sample circle rendering is not current production behavior. Export dimensions/options and the annotation-capacity rejection remain unchanged.

Main's newer serial-cancellation test coverage is absent from the migration branch. That is a test-only branch difference: no corresponding application cancellation change exists between these revisions. Updated smoke-test expectations for scene format 16/manual detectors likewise do not introduce new application behavior.
