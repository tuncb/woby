# Performance work suggested by the large-file baseline

This is a proposed investigation order, based on the [October 2026 measurements](large-file-stress-results.md). These changes have not been implemented. Preserve correctness, diagnostic completeness/truncation reporting, scene semantics, and the original corpus when comparing a future implementation.

| Order | Problem and measured evidence | First investigation | Rerun workload |
| --- | --- | --- | --- |
| 1 | Intermittent native-loader termination with `0xC0000374`: BeTSSi ×100 failed in the first sweep and one of three headless repeats; tubes ×1,000 failed once | Capture a crash dump and stacks; examine failure/cleanup paths around freeform limits. The current evidence does not isolate the faulty allocation or thread. | `load --headless --select BeTSSi_mod_NURBS_x00100 --rounds 3`; preserve ordinary rejection as well as crash cases |
| 2 | Unsupported inputs consume large resources before failure: keycap ×1,000 rejected after 244.69 s; orchard loaded on CPU for 57.22 s before a GPU-size rejection | Measure when final count/byte limits become knowable. Evaluate earlier budget checks and cancellation before expensive tessellation or GPU staging. | Full load sweep, especially keycap ladder and orchard |
| 3 | Analysis computation can succeed while display fails: BearTrap UV metrics completed, but the heatmap exceeded a 32-bit buffer limit | Profile expanded per-triangle display storage; make the limitation visible early. Investigate chunked/indexed display representations and capacity checks before preparing unusable buffers. | `uv --select BearTrap`; successful capture is a required check, not just `analysis.results` |
| 4 | Analysis memory greatly exceeds import memory: Bennu 2.8 GiB load case versus 22.95 GiB mesh suite; BearTrap mesh analysis hit the 38 GiB guard | Measure simultaneous ownership of snapshots, world meshes, topology, findings, prepared display data and GPU upload copies. Separate retained caches from transient duplication. | `mesh --select bennu --select BearTrap`; compare phase peaks and identical counts |
| 5 | UV edits repeatedly cost seconds: San Miguel metric/threshold/range changes about 15 s; BearTrap several metric changes about 114 s | Profile geometry rebuilds, quality/statistics work and display preparation separately. Determine which presentation edits can reuse immutable geometry/results or select already prepared values. | `uv --select san-miguel`; include no-op metric and changed-metric controls |
| 6 | Annotation edits block interaction: Bennu line create/move/reshape and rectangle projection each took about 7.5 s, with matching `scene_state` frame stalls | Profile projection inputs and candidate geometry; examine spatial filtering, reuse, and cancellable worker execution with owned snapshots. | `annotation --select bennu`; verify projected geometry and save/reopen |
| 7 | San Miguel analysis Properties costs about 46 ms per frame: visible/hidden/restored gives 12.32/29.01/12.39 FPS and ImGui 46.75/0.16/46.45 ms; scene/helper submission still costs about 30 ms | Profile Properties and repeated queries across 2,203 groups; cache derived values and inspect scene/helper traversal separately. The left-pane RPC toggle does not hide Properties. | `analysis-display --select san-miguel`, then the native pane toggle sequence; lock drawable dimensions and retain camera state |
| 8 | Dense overlays and point sprites dominate GPU time: BearTrap combined view 4.95 FPS / 202 ms GPU; 10M points slow sharply as point size grows | Capture GPU timings per pass, vertex/fragment workload and overdraw. Compare edge, point and combined passes independently; consider representations and optional detail controls only after profiling. | `render --select BearTrap`; repeated 10M/100M point-size ladder |
| 9 | First-use display updates stall the main loop: BearTrap import had a 2.24 s `pending_io` frame; Bennu quality changes had roughly 3 s `view_setup` frames | Separate worker preparation, main-thread resource creation, transfer and synchronization. Move eligible CPU preparation off the UI thread and measure upload budgeting. | Import plus four quality switches; compare longest logged frame with steady FPS |
| 10 | Complete diagnostic export is a substantial operation: Powerplant 1.335 GB / 93.77 s; San Miguel 1.550 GB / 115.68 s | Profile snapshot copying, JSON formatting and writes; assess progress/cancellation responsiveness and useful export granularity without silently discarding findings. | `mesh --select powerplant --select san-miguel`, plus export-cancel in `analysis-display` |

Distance comparison also needs a stability investigation alongside the loader issue. San Miguel twice lost the connection around 281–286 s and recorded exception exit code `0xC0000409`, including with automatic detectors disabled. Cleanup raced process exit, and no stack is available; capture a dump before attributing the failure to a particular allocator or algorithm. Both runs stayed below the sampled memory guard.

Comparison has an additional capacity boundary: its current display representation reserves up to twelve vertices per triangle, so the 32-bit buffer limit is reached at 11,184,810 triangles per side with 32-byte vertices. This is separate from the source mesh's ability to open. Bennu still spent 162 s before this rejection with automatic detectors disabled. The comparison results in the main report distinguish capacity rejection, resource-guard termination, and successful distance measurements.

For each change, compare the same Release build settings, machine, corpus hashes, camera state, window dimensions and workload order. Repeat important cases with alternating order. Record import/ready latency, longest main-loop stalls, steady FPS, CPU/GPU stage times, memory peaks and retained memory separately. A faster truncated result, hidden geometry, missing heatmap, or altered detector count is not a performance improvement.

Further experiments should expand native pointer hover/selection beyond the San Miguel smoke check, add fixed-resolution 1080p/4K rendering, control storage-cache conditions, compare unequal/partially overlapping inputs, test plugin formats and run a longer memory soak. The early scripted runs did not retain actual drawable dimensions; a reproducible resolution control is the first harness improvement before cross-build FPS comparisons. The current report identifies which paths were measured; these additions should not be treated as already covered.
