Changes

  1. Select the coordinate storage once, outside the inner loop. Keep checked access for externally supplied geometry.
  2. Build block bounds in parallel. Reduce precise group bounds in source order to preserve equal-value and signed-zero behaviour.
  3. Run the ordered fingerprint pass beside spatial preparation. Preserve the existing hash recurrence and all input bit patterns.
  4. Allocate the exact tree size, build independent subtrees in parallel, then merge their parents. Preserve the original preorder layout.
  5. Limit annotation helper threads during concurrent preparation. This leaves capacity for source-index and point preparation.

Correctness and resource use

  • The complete Release build has no warnings. All 96 CTest entries pass: 87 default, 8 slow, and 1 graphics.
  • Every accepted headless run matches the original saved fingerprints and digests of every block bound, precise group bound, ordered triangle offset, and tree field.
  • All three candidate screenshots are byte-identical to two original screenshots. The third original differs only in four pixels of the bottom-left grid-spacing label, outside the model and grid. The rendered scene matches in every run. Peak private commit is 10.780 → 10.782 GiB.
  • Tests cover each coordinate-storage path, nonfinite values, signed zero, irregular groups, invalid indices, tree boundaries, serial/parallel equality, cancellation, callback errors, and helper limits.

Annotation preparation: 18.31 → 17.41 CPU seconds. Combined post-load preparation: 25.62 → 23.36 CPU seconds. CPU time sums work across threads. These reductions are smaller than the elapsed-time reductions because parallel execution supplies much of the gain.
