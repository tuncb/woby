Keep 16 as the current latency baseline. Eight workers take 3.341 s; sixteen take 2.906 s; thirty-two take 2.803 s. Compare CPU seconds as well as wall seconds. Sixteen logical processors share eight physical cores.

The block-size setting changes the algorithm. At 4 MiB or more, the multi-worker file path selects long native read ranges, double buffers 256 KiB reads, and decodes while the next read is pending. Thus 8 and 16 MiB settings still produce 16 ranges; they do not enlarge the native read buffer. At 1 and 2 MiB, thousands of bounded blocks and async tasks increase allocation, merge, and thread overhead. read_bytes configures non-seekable streams, so changing it does not tune these file reads.

The modern number decoder gives a small full-load opportunity. With the same parser grammar, the research build of fast_float 8.3.2 takes 2.794 s versus 2.906 s at 16 workers: 3.8% less parser wall time. Holding all other work constant predicts about 0.11 s saved to Ready, or 0.8% of this full-load median. That prediction has not been verified in the production viewer. Upstream fast_float release.

For this ASCII OBJ, the new decoder still uses the byte/SWAR path. Its explicit eight-digit SIMD helper is selected for char16_t, not char. Updating the decoder does not automatically create an AVX2 OBJ parser.

The sampled position rows have six values: XYZ and RGB. The prototype parses and checks all three color values, then discards them for these rows. Woby retains the coordinates. Such rows need twice as many number conversions as plain XYZ rows. An unused-color validation fast path is a useful further parser trial, but it must preserve accepted syntax and rejection of non-finite/out-of-range values. The six-value observation comes from 4,096 sampled rows; it is not a full-file field-count census.

The current simple-face path does not fit the sampled BearTrap faces. PrototypeSimpleFace accepts positive position-only references. All 4,096 sampled face rows have three slash references. The probe converts the first position, sees the slash, and falls back to ParseFace. The general face parser is the largest parser cycle hotspot. A positive v/vt triangle path, or avoiding the failed probe, is a concrete next experiment. Keep the general path for negative references, normals, polygons, and diagnostic behavior.

Whole-file preloading is a poor trade in this control. It allocates and retains the 7.11 GB input before parsing. That preparation adds several seconds; peak working set rises to about 15.7 GiB. Memory parsing can reduce input calls but has 1,695 bounded tasks rather than 16 native ranges. This is not a clean IO-only subtraction, and it is not a memory-mapped-file test.

All 48 parser samples use fresh processes, warmed input, rotated variant order, and the same ordered output fingerprint. The fingerprint checks position doubles, rendered float UV/normal values, shapes, indices, material IDs, smoothing, lines, and points. Material payloads and colors are not checked. It does not prove identical low bits for every prototype double UV/normal, or correctness for all OBJ grammar. Add full-precision and grammar tests before adopting the decoder.

Parser design and next experiments
  • Separate numeric decoding, face-reference parsing, allocation, and merge hot paths in the profile. Preserve the general grammar as a fallback for a measured triangle fast path.
  • Try a persistent bounded worker pool with more balanced tasks. Current long ranges are balanced by bytes, not decode cost. Avoid a thread launch for every tiny block.
  • Test batched newline/space/slash classification with AVX2 only if structural scanning is a hotspot. Decimal conversion already uses a fast scalar/SWAR algorithm.
  • Investigate counted output ranges or fewer simultaneously live chunk/merged arrays. A full sizing pass adds input work; measure its total cost and memory reduction.
  • Keep double source coordinates and deterministic source IDs. Float-only parsing can make the benchmark faster while reducing model accuracy.

5a. SIMD inside the OBJ parser

The parser already uses SIMD for byte search and bulk copying. Its main number and face decoders operate on one number or reference at a time. SWAR means several digit bytes packed into one 64-bit integer register. This is useful data parallelism, but it does not use the SSE/AVX vector registers.

Explore an assumed branch recovery cost

This calculation assigns the same penalty to every reported miss and compares its nominal sum with the sampled user-mode cycle count. Actual recovery latency and overlap are unmeasured; this is not a wall-time prediction.

The position-only face probe still decodes an index before it falls back for the sampled slash format. Its source and sampled CPU cost give a specific redundant-work target. A broad branchless rewrite would need evidence that its added loads or calculations cost less than the existing predictable paths.

A positive v/vt triangle needs six integer conversions. The failed position-only probe adds a seventh by decoding the first position again. The general path also checks the optional normal and index formats for each corner. A measured common-format decoder can remove that repeated work while preserving the general fallback.

Measurement scope and remaining gaps
  • User-mode core events only; Windows file-cache and fault handling in kernel mode are excluded.
  • Event-based sampling has skid and attribution bias. Ratios are estimates, especially within individual functions.
  • No observed samples does not prove zero events. The minimum permitted core-event interval is 25000.
  • Dispatch stalls overlap; op-queue-empty cycles are not a complete frontend-bound measurement.
  • Demand-fill sources and selected L2 request outcomes are not universal cache hit rates or physical DRAM traffic.
  • IBS counters are unavailable in this Windows session; precise load latency, dependency chains, and false-sharing attribution remain unmeasured.

6. The long annotation pass: validated replays

The pass visits all 227,315,958 triangle corners. For each corner it hashes the vertex ID and three render-coordinate bit patterns, reads precise coordinates, and updates float block bounds and double group bounds. There is one model group, so simply parallelizing groups gives no benefit. The current pass calls hashing, generic position, and finite-coordinate helpers in the inner loop.

In the isolated replay, replacing helper calls with the same inline hash, direct OBJ source-coordinate access, and inline finite checks reduces the combined pass from 3.508 s to 2.233 s. This is a measured kernel result with matching outputs. It is not a measured end-to-end production speedup.

The direct path needs validated immutable OBJ geometry and the correct source-position map. A production change must keep generic storage paths and cancellation behavior. The ordered fingerprint is part of saved annotation identity; a different parallel hash cannot silently replace it. Bounds can be parallelized independently, but compare extra passes, temporary memory, and overlap with point preparation.

Inlining the hash alone changes the combined median from 3.508 s to 3.366 s. Most of the combined gain comes from coordinate access and finite checks. The direct bounds-only pass takes 1.519 s on one thread and 0.269 s on eight threads. The ordered hash-only pass still takes 1.112 s.
