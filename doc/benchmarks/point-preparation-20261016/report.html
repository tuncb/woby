What changed

  1. For one group, scan the indices in their original order. If first-use IDs form a contiguous prefix, count that prefix without marker accesses. Materialise its ordered membership once. This property is checked from the indices; it is not assumed from the importer.
  2. If an ID skips ahead, preserve the proven prefix and continue with one visited bit per render vertex. Keep the original marker path for multiple groups. Stop the scan once all vertices belong to the group. Validation still checks all indices before this shortcut.
  3. Fill sorted point positions and point-ID-indexed colours in parallel batches. Workers write disjoint output ranges. Each gather uses at most three helpers plus its caller. All point key, sort and gather passes share the helper budget with annotations after accounting for coordinator jobs: at most three helpers per branch on this machine. Standalone key and sort work can use the full shared limit.
  4. Release membership scratch before building the hierarchy. Keep first-use order, Morton tie order, UV seam vertices, colours, tree nodes, proxies and navigation cuts unchanged.

Memory and CPU cost

The original marker array uses 307,315,128 bytes on BearTrap. The ordered path uses zero marker bytes in every final BearTrap candidate run. A general single-group input needs at most 4,801,800 bytes for visited bits at this vertex count. The membership output itself still uses 153,657,564 bytes.

Median native viewer peak private commit is 9.522 → 9.522 GiB. This whole-process peak can occur during import, before point preparation. The marker reduction must not be read as an equal reduction in the whole-process peak.

Isolated point preparation uses 7.047 → 6.281 CPU seconds. Complete post-load preparation uses 28.688 → 27.938 CPU seconds. Resizing output buffers, all gather passes, scratch release and competition with annotations are included in the appropriate complete-path timers.

Annotation overlap and Ready

The overall Ready median is 1.141 seconds lower. The candidate is faster in 9 of 10 pairs. Median paired savings are 0.591 seconds, with a range of -0.059 to 3.821 seconds. All valid samples are retained. Import and frame timing vary by much more than the expected point-stage contribution to Ready. The overall difference of medians must not be treated as the point-stage saving.

Ready waits for both the point/model branch and the annotation branch, then for publication and upload. Saving time in points cannot be added directly to Ready. The earlier trace allowed about 0.64 seconds of direct Ready improvement if annotation time stayed fixed. This change also alters contention for memory and CPU; only the paired native viewer result above measures its net effect.

Checks and experiments

The Release build completes without warnings. All 106 CTest entries pass: 96 default, 9 slow and 1 graphics. Focused tests cover first-use order, word-boundary fallback, partial and empty groups, overlapping groups, invalid trailing indices, RGB alignment, cancellation, worker exceptions and exhausted helper budgets.

The benchmark now checks all point-cloud output outside the timer. It also checks annotation output in combined runs. Nineteen native captures are pixel-identical; one differs in four pixels of the bottom-left grid label. A candidate viewer capture and pixel comparison records are included with the evidence.

The first bitset-only experiment reduced storage but slowed membership (1.337 → 1.500 seconds, including validation). Parallel gathering still reduced its complete point median from 3.302 to 2.843 seconds. The first prefix implementation removed marker storage, but its new-vertex branch remained expensive. All three membership pairs and the interrupted campaign note are retained. The final scan uses an arithmetic count and branches only on an out-of-order ID or completion.

The first full implementation made Bennu's isolated point branch faster but exposed a scheduling regression in combined preparation: 1.429 → 2.140 seconds. Its point key and radix passes could take the helpers just before the annotation key pass started. That pass then ran with too few workers for its whole duration. Limiting all point passes to their share of the budget removed the observed 2.1–2.35 second candidate spikes. A regression test checks the maximum helper use while coordinator slots are occupied. The earlier results and trace remain in the evidence; they are not mixed into the final comparison.
