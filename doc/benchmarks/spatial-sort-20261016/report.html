What changed

The first pass partitions keys by their high 13 bits. Chunk prefixes follow input order. Each resulting range then uses two stable local passes. One scan supplies both local histograms. Long ranges start first, but all ranges write to disjoint storage, so worker order cannot change the result.

Inputs below 1,048,576 keys use the existing byte sort. If one partition contains more than one quarter of the input, the byte sort keeps the remaining work parallel. It reuses the first scan to skip constant bytes. All-equal inputs return without moving keys. The helper limits used by both preparation branches remain in force.

The full key scratch array remains the same size. Additional partition tables and local histograms use less than 1 MiB per active sort on this machine. Native peak private commit was 9.521 GiB at baseline and 9.522 GiB in the candidate. These are whole-process peaks, which can occur during import.
