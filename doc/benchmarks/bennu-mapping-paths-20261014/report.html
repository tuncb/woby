Bennu: fallback versus staged mapping

The staged mapper imports Bennu in 2.091 s versus 2.684 s with the current fallback: 22.1% less CPU load time. Peak import memory is effectively unchanged.

Bennu has 8,933,524 source positions, 53,600,508 triangle corners, no normals, and no UVs. The input is 815,866,103 bytes. The current application selects its 4-byte position lookup. The comparison build permits the same file through the 12-byte staged mapper.

Complete CPU imports

Five alternating pairs use deferred preparation, as in the viewer. Three further pairs use eager preparation. Each trial starts a fresh process, warms the same input first, and uses the default parser workers and up to eight gather workers. These measure the complete importer, including normal generation, bounds, and release of parser data. Validation runs after the time and memory snapshot.

Do we need the fallback?

For Bennu, the staged mapper is faster. CPU importer peak private commit differs by 0.05 MiB; matching viewer peak private commit changes by +2.31 MiB (+0.09%). Both paths retain the same mesh buffers. The smaller fallback table does not reduce the importer peak. Removing the position-only exclusion is supported by this comparison for Bennu.

The first viewer controls compared the stock executable with a mapper override. The native override executable is 3.77 MiB larger, which could affect the small memory difference. The headline viewer tables use matched override builds for both paths, with identical executable and code-section sizes. The earlier controls are a separate capture group.

The current staged routine maps faces only. Lines, explicit points, and vertex clouds still use the existing primitive builder and vertex-ID table. Extending or replacing that handling needs implementation work; those primitives do not inherently require the old face mapper.

The freeform exclusion is conservative. Curves and surfaces are evaluated separately and appended after polygon geometry. This comparison did not test whether polygon faces in a freeform file can use staged mapping. It does not establish that freeforms require the old mapper.

The sparse-input guard is a temporary-memory choice, not a correctness requirement. When many source positions are unused, the 4-byte primary table and bounded keys can be smaller than a 12-byte slot for every position. This comparison did not measure sparse inputs or establish their whole-process peak-memory difference.

Production path selection is unchanged. This is an isolated comparison, not a routing change. Other position-only models still need a representative regression run before a general routing change.

Correctness and validation

The full Bennu buffers are compared directly in separate eager and deferred verification runs. This includes vertex bytes and generated normals, ordered triangle IDs, source positions and indices, position maps, group fields, origin, and bounds. Every timed run also computes a matching full-mesh fingerprint outside the measured interval.
