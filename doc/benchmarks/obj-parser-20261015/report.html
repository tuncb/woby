What changed

Decode each common face once

Triangles and quads use a direct decoder for positions, UVs and normals, including relative references. Eight-byte integer parsing replaces repeated general conversions. A face is published only after its full syntax is valid.

Convert only the values that are needed

Short decimal coordinates use integer operations and an exact floating-point conversion. Long decimals and exponents retain the full decoder. Unused vertex colors are validated without conversion. Position weights keep full precision.

Reserve buffers before decoding

A bounded pass counts attributes and face references. The decoder reuses its line offsets. Exact reservations remove repeated growth copies and support triangles, quads and general polygons. The general decoder retains room for its error lookahead.

Balance work across the file

Persistent workers take bounded blocks from a shared queue. Short work units reduce the long tail from unequal read ranges. The collector preserves file order and releases decoded input text. Cancellation and worker failures join all workers.

Validate and copy indices with AVX2

Three vector registers hold eight complete index triplets. Uniform flags permit vector validation, relative-index adjustment and copying. Mixed flags and tails use the scalar path. Non-AVX2 builds retain scalar support.

Keep the production path free of timers

The profiling tools instrument generated header copies. Production parsing has no new timing calls. The benchmark now records full-precision fingerprints, process CPU time and memory peaks.

Validation passed

Output and error behavior remain checked

  • All 98 configured CTest entries passed: 88 default entries, 9 slow entries and 1 graphics entry.
  • Release application and optional profiling tools built with the vs2026-vcpkg preset, with no compiler or linker warnings.
  • AVX2 and scalar parser builds each passed 11 cases and 652,443 assertions. AddressSanitizer passed the same parser suite with no findings.
  • 100,000 decimal inputs were compared bit for bit against the full number decoder. Tests also cover malformed indices, all offset-flag combinations, vector tails and polygon-limit lookahead.
  • Seeded file tests compare complete geometry, weights and freeform statements across worker counts and block boundaries. They check long lines, queue reuse, first-error locations and cancellation before caller storage reuse.
  • All 50 real-file parser runs produced matching ordered geometry fingerprints. The precise hash covers double positions, UVs and normals, shape names, indices, face sizes, material IDs and smoothing IDs.

Real-file fingerprints do not cover material payloads or unused colors. The unit suites check color acceptance, weights, material behavior and freeform data. No precision reduction or unchecked index path was used to obtain the gain.

Method and reproduction

The original revision is 06b794027e3a8ca6da9725596c909167256472e5. Both versions use the same compiler, Release settings and 16-worker budget. Original parser headers were preserved before the edits; the benchmark harness includes the same CPU, memory and precise-hash instrumentation for both versions. The full CPU import baseline was built from a separate clean worktree at that revision.

Each input is read before each sample. Before/after order alternates by round and model. The runner waits for two 0.5-second CPU samples at or below 15%, and checks for known build, test, viewer and profiler processes before and after each run. The power scheme stays fixed. Five pairs show this machine’s observed variation; they are not a claim about every CPU or cold-storage load.

The source audit used Performance Mode. This campaign uses Balance Mode, so the before/after result is taken from this campaign only. Diagnostic profiler timings and exploratory runs are excluded.

cmake --preset vs2026-vcpkg -DWOBY_BUILD_RAPIDOBJ_PROTOTYPE_BENCHMARK=ON
cmake --build --preset vs2026-vcpkg --config Release --target woby_parser_benchmark woby_obj_prototype_benchmark
